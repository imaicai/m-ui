# M-Ui

### **最简单的代理面板**

**轻量 · 安全 · 稳定 · 易维护**

**当前版本：v1.5.25**

面向个人服务器的轻量级 Xray Web 管理面板。  
前后端由一个 Go 服务承载，默认围绕 **VLESS + RAW + REALITY + XTLS Vision** 提供节点创建、订阅管理、运行监控与服务器管理能力。

[GitHub 项目主页](https://github.com/imaicai/m-ui) · [提交问题](https://github.com/imaicai/m-ui/issues)

</div>

## ✨ 项目定位

M-Ui 不追求堆叠大量协议和复杂选项，而是尽量把常用、可靠的代理服务器管理流程做得更简单。

它更关注：

- **开箱即用**：一条命令完成安装，前端、后端和管理脚本一起部署。
- **少配置**：新建节点时自动完成公网 IP、国家代码、节点名称、端口、UUID、REALITY 密钥和 Short ID。
- **低干扰**：节点修改优先热更新对应 Xray inbound，尽量避免影响其他节点。
- **安全默认值**：密码、Session、CSRF、配置文件权限和 systemd 运行参数默认采用更严格的策略。
- **稳定优先**：普通更新不盲目追新 Xray；完整更新才主动刷新核心，并提供校验与回滚。
- **轻量部署**：Go 单服务运行，不需要 Node.js、npm 或额外 Web 运行时。
- **适合共存**：默认使用独立端口，不强占 80 / 443，可与 1Panel、Nginx、其他网站和服务共存。

## 🧩 默认节点方案

新建节点默认采用：

~~~text
VLESS + RAW + REALITY + XTLS Vision
~~~

创建节点时，M-Ui 会自动完成：

1. 🌍 识别服务器公网 IP 与两位国家代码；
2. 🏷️ 自动生成节点名称，例如 **US01 / JP01 / DE01**；
3. 🔌 自动选择可用高位端口；
4. 🔑 自动生成 UUID；
5. 🔐 自动生成 REALITY X25519 密钥和 Short ID；
6. 🌐 默认使用 **www.apple.com:443** 作为 REALITY 目标；
7. ✅ 使用当前 Xray 执行真实配置校验；
8. 💾 保存持久配置；
9. ⚡ 优先通过 HandlerService 热更新目标 inbound；
10. 🛟 热更新不可用时自动回退完整 Xray 应用流程。

节点名称、分享地址等纯展示信息发生变化时，如果不影响实际 Xray inbound，不会为了这些改动无意义地重载节点。

## 📊 仪表盘

仪表盘用于快速确认代理与服务器状态。

### 顶部概览

- **代理服务**：Xray 是否正常运行、服务器运行时间；
- **节点状态**：节点总数、启用和停用数量；
- **代理流量**：全部节点累计上下行代理流量；
- **服务器状态**：综合 CPU、内存和磁盘负载提示。

### 服务器资源

当前按以下顺序显示：

~~~text
CPU → 磁盘 → 内存 → SWAP
~~~

资源区域用于观察服务器即时负载；下方的 **服务器实时网络** 单独展示服务器网卡最近采样的上下行变化。

### 节点概览

仪表盘直接展示常用节点信息，包括：

- 节点名称与国家标识；
- 启用 / 停用状态；
- 节点累计流量；
- 端口；
- 快速复制节点链接。

## 🔗 订阅管理

首次初始化时，M-Ui 会自动创建一个 **默认订阅**。

默认订阅：

- 始终排在第一位；
- 不允许删除；
- 自动跟踪当前全部节点。

自定义订阅可以单独选择需要包含的节点。

新建或主动修改订阅后缀时，使用高熵随机地址，并限制为 **20–80 位**，允许：

~~~text
字母 / 数字 / - / _
~~~

订阅地址示例：

~~~text
https://你的域名或IP:端口/sub/随机后缀
~~~

历史已经存在的订阅地址会继续兼容，不会因为更新而强制失效。

## ⚙️ 一键安装

### 推荐系统

- Ubuntu
- Debian
- Rocky Linux
- AlmaLinux

系统需要支持 **systemd**。

### 使用 wget

~~~bash
bash <(wget -qO- https://raw.githubusercontent.com/imaicai/m-ui/main/install.sh)
~~~

### 使用 curl

~~~bash
bash <(curl -fsSL https://raw.githubusercontent.com/imaicai/m-ui/main/install.sh)
~~~

安装器会自动处理：

- M-Ui 编译与部署；
- Xray 安装与版本管理；
- systemd 服务；
- 管理数据目录；
- 防火墙端口；
- 安全权限；
- 网络基础优化；
- 首次管理员初始化。

## 🛠️ 自定义安装参数

例如自定义面板端口、用户名和密码：

~~~bash
MUI_PORT=3001 MUI_ADMIN_USER=customuser MUI_ADMIN_PASS='YourStrongPassword' \
  bash <(wget -qO- https://raw.githubusercontent.com/imaicai/m-ui/main/install.sh)
~~~

高级兼容参数：

~~~bash
MUI_XRAY_USER=root ...
~~~

一般 **REALITY-only** 部署无需手动指定 Xray 用户。

检测到历史 TLS 节点时，安装器会优先采用兼容方式，避免破坏现有证书读取权限。


- 节点；

- 面板设置；
- 证书路径；
- 累计流量；

SSH 管理菜单提供：


## ⚡ Xray 运行机制

M-Ui 尽量减少一次普通管理操作对其他节点的影响。

### 节点变更

新增、启停、删除或修改运行参数时：

1. 生成新的完整配置；
2. 使用 **xray run -test** 校验；
3. 计算受影响的 inbound；
4. 优先使用 **HandlerService** 热更新；
5. 持久化完整配置；
6. 热更新失败时才进入完整应用 / 恢复流程。

### 面板重启

M-Ui 面板进程重启和 Xray 重启是两件事。

如果运行配置没有变化且 Xray 健康，重启面板不会无条件重启 Xray。

## 🛡️ 安全设计

| 项目 | 当前策略 |
|---|---|
| 🔑 **密码** | Argon2id |
| 🎲 **首次密码** | 安装时随机生成，不使用固定默认密码 |
| 🍪 **Session** | HttpOnly + SameSite=Strict |
| 🧷 **写操作** | CSRF Token + Origin / Sec-Fetch-Site 同源校验 |
| 🔒 **HTTPS** | 有效证书下支持 HTTPS，并发送 HSTS |
| 📁 **数据文件** | /etc/m-ui/state.json，权限 0600 |
| ⚙️ **Xray 配置** | root 场景 0600；专用 xray 用户场景 root:xray + 0640 |
| 👤 **Xray 用户** | REALITY-only 默认优先使用专用 xray 系统用户 |
| 🚦 **登录失败** | 按来源限制并控制失败状态缓存规模 |
| 🩺 **健康接口** | 仅返回最小健康状态，不公开版本 |
| 🧱 **systemd** | NoNewPrivileges、PrivateTmp、ProtectKernelTunables 等限制 |
| 🎯 **订阅地址** | 新建 / 修改地址使用高熵随机后缀 |

旧密码数据仍可兼容登录，验证成功后会自动迁移到新的 Argon2id 哈希。

## 🌐 网络与稳定性策略

M-Ui 只使用相对保守、可解释的系统参数。

内核支持时使用：

~~~text
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr
net.ipv4.tcp_mtu_probing=1
~~~

RAW 入站使用：

~~~text
tcpKeepAliveIdle     = 60
tcpKeepAliveInterval = 15
~~~

M-Ui **不会自动安装第三方魔改内核**，也不会批量写入来源不明的 TCP 调优参数。

## 🧠 Xray 版本策略

普通更新不会盲目追随最新 Xray。

M-Ui 会记录已验证版本：

~~~text
/etc/m-ui/xray-version.lock
~~~

普通重复安装优先继续使用该版本。

只有显式执行完整更新时才主动刷新 Xray。刷新过程中会：

1. 备份旧二进制；
2. 安装目标版本；
3. 使用现有节点配置真实测试；
4. 重启并检查服务；
5. 失败时自动尝试恢复上一版本。

## 🖥️ 系统设置

Web 面板可以调整：

- 🏷️ 面板名称；
- 🔌 面板端口；
- 🧭 面板 URL 根路径；
- 🌐 节点域名；
- 🔐 TLS 证书路径；
- 👤 管理员用户名；
- 🔑 管理员密码。

修改普通设置直接生效。

修改管理路径后会自动切换入口；修改管理员账号后需要重新登录；修改面板端口时会重启面板进程。

右上角的 **管理员账号区域** 可以直接进入系统设置。

系统设置中的 **系统升级维护** 会显示当前面板版本与开源仓库版本。每次登录后台时会自动检测一次；之后不会自动轮询，需要时可点击版本区域右侧的刷新图标手动重新检测。版本一致时升级按钮显示“暂无更新”并保持禁用；仅当开源仓库版本更高时，按钮才会变为绿色并显示“进行完整更新”。真正开始更新时，服务端仍会再次校验版本，避免同版本重复更新。完整更新会在后台启动与 SSH 菜单“完整更新 m-ui”相同的更新流程：更新前端、后端、SSH 管理脚本与 Xray Core，同时保留现有账号、节点、订阅和面板设置。网页与 SSH 更新共用同一套容错下载链路：已有基础依赖时不再重复刷新系统软件源；源码获取支持 Git clone 与 ZIP 回退；Go 编译使用持久缓存并依次尝试本地缓存、官方模块源、goproxy.cn、goproxy.io 与直连；网页后台任务取消默认启动超时并固定 HOME/GOCACHE/GOMODCACHE。Xray 在线更新失败时，如果本机已有稳定版本，会自动回滚/保留稳定 Xray 后继续完成面板更新，避免单一网络波动导致整次升级失败。v1.5.25 起网页完整更新改为静默流程：不再显示确认弹窗、进度弹窗或进度条。点击“进行完整更新”后，按钮只显示“后台更新中…”，浏览器不再读取后台进度状态，因此面板重启时的短暂断线不会被误判为更新失败。浏览器只通过公开的面板版本接口静默检测新版是否已经启动；检测到目标版本后立即重新打开面板入口。由于 m-ui 重启会清空当前登录会话，此时会直接显示登录页面；能够加载登录框即表示新版面板已经成功启动。页面同时提示：完整更新完成后面板会自动重启并进入登录页面，请重新登录。

移动端会自动切换为固定顶部导航，页面滚动时始终保持可见。顶部只保留菜单图标；“重启面板”移动到菜单内并位于“退出登录”上方，点击菜单以外区域会自动收起菜单。 顶部品牌 Logo 与名称以及桌面端左上角品牌区域均可直接返回仪表盘；移动端菜单中的“重启面板”恢复为原来的中性灰色样式。登录页面使用动态视口居中布局，手机登录框始终按当前可视区域上下左右居中。设置页面中的输入说明会排列在对应输入框下方，避免窄屏下横向拥挤。节点管理在手机端按“新手说明 → 搜索框 → 清空全部节点流量 / +新建节点 → 节点列表”顺序排列。

## ⌨️ SSH 管理菜单

安装完成后，普通用户只需要记住一个命令：

~~~bash
m-ui
~~~

执行后会进入交互式管理菜单。菜单顶部会动态读取当前版本、运行状态、公网 IP、国家、管理员账号、端口、根路径、面板地址和 BBR / FQ 状态。

菜单示例（以下仅展示格式，实际内容由你的服务器动态读取）：

~~~text
m-ui 管理脚本 · MiniJet
-------------------------------------------------------
版本: 1.5.25
状态: 运行中
公网IP: YOUR_SERVER_IP    国家: XX
登录用户: ADMIN_USER    端口: PANEL_PORT    根路径: /PANEL_PATH/
面板地址: http://YOUR_SERVER_IP:PANEL_PORT/PANEL_PATH/
网络加速: BBR + FQ
-------------------------------------------------------
 1. 一键安装 m-ui
 2. 删除卸载 m-ui 【包含卸载所有配置】
 3. 完整更新 m-ui 【前端、后端、脚本、Xray】
-------------------------------------------------------
 4. 变更 m-ui 面板设置 【用户名密码、登录端口、根路径、还原面板】
 5. 关闭、重启 m-ui
-------------------------------------------------------
 6. 查看 m-ui 运行日志
 7. 一键原版BBR+FQ加速
 8. 刷新IP配置及参数显示
-------------------------------------------------------
请输入选项 [1-8，CTRL+C退出]
~~~

通过菜单可以完成：

- 安装、卸载与完整更新；
- 管理员用户名、密码、端口和根路径调整；
- 面板访问设置还原；
- 面板关闭、启动与重启；
- 实时运行日志查看；
- 原版 BBR + FQ + PMTU 配置；
- 公网 IP、国家和面板参数重新检测。

> **关于 `m-ui-ctl`：** 控制脚本仍然保留，主要用于自动化、脚本调用和兼容已有运维流程；普通用户无需记忆这些命令，日常管理统一使用 `m-ui` 即可。
